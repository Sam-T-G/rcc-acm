How to run it

  • One laptop per team of 3, the same as the real contest. One person types. The other two read problems and plan.
  • Split the set. The typer starts on 1. Reader A reads 2 to 5. Reader B reads 6 to 8. When a reader has a plan ready, they take the keyboard.
  • Stuck for 10 minutes? Write the code on paper and let the next person type.
  • Run the samples before you submit. At the regional, every wrong submit on a problem you later solve adds 20 minutes to your time.
  • Print the cheat sheet. The SoCal regional lets you bring books and paper notes, but no phones, laptops, or USB drives (SoCal contest rules). The languages are C, C++, Java, Python 3, and Kotlin.
  • Submitting: make a free account at open.kattis.com, open the problem, click Submit, pick C++, and paste or upload your file. Accepted means it passed every hidden test.

Problems

  1. 1

    Is Y a Vowel?

    2023 ICPC North America Qualifier · Kattis difficulty 1.2

    Count the vowels in one lowercase word, first without y and then with y.

    Input: one word. Uses: loop over a string, if/else.

    Starter code
    Reads the input for you. Fill in the middle.
    #include <iostream>
#include <string>
using namespace std;

int main() {
    string word;               // one lowercase word
    cin >> word;

    int withoutY = 0, withY = 0;
    for (char c : word) {
        // your code here: count the vowels
    }

    cout << withoutY << " " << withY << "\n";
}
    Hint

    Count a, e, i, o, u in one counter and y in another. The second answer is both counters added.

    Common trap

    Printing the two numbers in the wrong order. The count without y comes first.

  2. 2

    No Duplicates

    2017 ICPC Mid-Central Regional · Kattis difficulty 1.4

    Print yes if no word in the line repeats, no if one does.

    Input: words until end of file. Uses: strings, set.

    Starter code
    Reads the input for you. Fill in the middle.
    #include <iostream>
#include <string>
using namespace std;

int main() {
    bool repeat = false;
    string w;
    while (cin >> w) {         // no count given: read words until the input runs out
        // your code here: has w shown up before?
    }

    cout << (repeat ? "no" : "yes") << "\n";
}
    Hint

    There's no word count, so read with while (cin >> w). It stops when the input runs out. Keep the words you've seen in a set<string>.

    Common trap

    Waiting for a count that isn't there. The output is lowercase.

  3. 3

    Quick Brown Fox

    2015 ICPC North American Qualifier · Kattis difficulty 1.4

    For each phrase, print pangram if it uses all 26 letters. Otherwise print missing and the missing letters in lowercase, a to z.

    Input: count, then whole lines with spaces. Uses: getline, tolower, output format.

    Starter code
    Reads the input for you. Fill in the middle.
    #include <cctype>
#include <iostream>
#include <string>
using namespace std;

int main() {
    int n;
    cin >> n;
    cin.ignore();              // drop the newline left after n

    for (int i = 0; i < n; i++) {
        string phrase;
        getline(cin, phrase);  // the whole line, spaces and all

        string missing = "";
        // your code here: which letters a to z never show up?
        // tolower(c) turns 'A' into 'a'

        if (missing == "") cout << "pangram\n";
        else cout << "missing " << missing << "\n";
    }
}
    Hint

    Read each phrase with getline. Mark letters in an array of 26 and use tolower so A and a count as the same letter.

    Common trap

    After cin >> n the newline is still in the input, so the first getline comes back empty. Call getline once before the loop to throw it away.

  4. 4

    Speed Limit

    2004 ACM ICPC Mid-Central Regional · Kattis difficulty 1.5

    Each log line has a speed and the total hours since the trip started. Print the miles for each data set, like 170 miles.

    Input: data sets until -1. Uses: nested loops, running total.

    Starter code
    Reads the input for you. Fill in the middle.
    #include <iostream>
using namespace std;

int main() {
    int n;
    while (cin >> n && n != -1) {   // data sets until a line with -1
        int miles = 0;
        for (int i = 0; i < n; i++) {
            int speed, hours;       // hours since the trip started
            cin >> speed >> hours;
            // your code here
        }
        cout << miles << " miles\n";
    }
}
    Hint

    Keep the previous time and add speed * (time - previousTime). Reset both to 0 for each data set.

    Common trap

    Using the time on the line as the hours at that speed. It counts from the start of the trip. Don't drop the word miles.

    ACM Contest Scoring

    2015 ICPC Mid-Central Regional · Kattis difficulty 1.5

    Given one team's submission log, print problems solved and the time score: the minute of each correct submission plus 20 for each wrong try on a problem they solved. This is the real ICPC scoring rule.

    Input: lines until -1. Uses: simulation, arrays indexed by letter.

    Starter code
    Reads the input for you. Fill in the middle.
    #include <iostream>
#include <string>
using namespace std;

int main() {
    int solvedCount = 0, timeScore = 0;

    int minute;
    while (cin >> minute && minute != -1) {   // log lines until -1
        char problem;          // a letter, A to Z
        string result;         // "right" or "wrong"
        cin >> problem >> result;
        int k = problem - 'A'; // A is 0, B is 1, ... handy for arrays of 26
        // your code here
    }

    cout << solvedCount << " " << timeScore << "\n";
}
    Hint

    Two arrays indexed by letter - 'A': wrong tries so far and solved or not.

    Common trap

    Charging 20 minutes for wrong tries on problems the team never solved. Those are free.

    Lines Per Hour

    2023 ICPC North America Qualifier · Kattis difficulty 1.6

    A team writes lph lines per hour for 5 hours. Print the most problems you can pick so they could still solve every one.

    Input: count, then one number per line. Uses: sort, take smallest first.

    Starter code
    Reads the input for you. Fill in the middle.
    #include <algorithm>
#include <iostream>
#include <vector>
using namespace std;

int main() {
    int n, lph;
    cin >> n >> lph;
    vector<int> lines(n);
    for (int i = 0; i < n; i++) cin >> lines[i];

    int count = 0;
    // your code here (sort(lines.begin(), lines.end()) sorts small to large)

    cout << count << "\n";
}
    Hint

    Sort the line counts small to large and take from the front while the total stays at or under 5 * lph.

    Common trap

    Using lph as the limit and forgetting the 5 hours. Not sorting is the other one.

    Nine Knights

    2017 ICPC Mid-Central Regional · Kattis difficulty 1.8

    Print valid if a 5 by 5 board has exactly 9 knights and none can attack another, invalid otherwise.

    Input: 5 by 5 grid. Uses: 2D grid, bounds checks.

    Starter code
    Reads the input for you. Fill in the middle.
    #include <iostream>
#include <string>
#include <vector>
using namespace std;

int main() {
    vector<string> board(5);
    for (int r = 0; r < 5; r++) cin >> board[r];   // 5 rows of 5 characters
    // board[r][c] is row r, column c. 'k' is a knight, '.' is empty.

    bool valid = true;
    // your code here

    cout << (valid ? "valid" : "invalid") << "\n";
}
    Hint

    Put the 8 knight moves in two arrays of row and column changes and check each one from every knight.

    Common trap

    Not counting the knights. Sample 3 has 8 knights that don't attack each other and the answer is invalid. Check the board edges before you read a square.

  8. 8

    Mouse Pursuit

    2024 ICPC Pacific Northwest Regional · Kattis difficulty 2.0

    CAUGHT adds cheese and glory, MISS takes them away. Print the totals from the events in the last k seconds. Totals can be negative.

    Input: count, mixed word and number lines, extra number at the end. Uses: long long, store then process.

    Starter code
    Reads the input for you. Fill in the middle.
    #include <iostream>
#include <string>
#include <vector>
using namespace std;

int main() {
    int n;
    cin >> n;
    vector<string> type(n);                 // "CAUGHT" or "MISS"
    vector<long long> secondsAgo(n), cheese(n), glory(n);
    for (int i = 0; i < n; i++)
        cin >> type[i] >> secondsAgo[i] >> cheese[i] >> glory[i];
    long long k;
    cin >> k;                               // k comes after all the events

    long long totalCheese = 0, totalGlory = 0;   // long long: these can pass 2.1 billion
    // your code here

    cout << totalCheese << " " << totalGlory << "\n";
}
    Hint

    k is on the last line, so store every event first, then add up the ones with seconds-ago at most k.

    Common trap

    int totals. 100,000 events of up to 1,000,000 cheese is 10^11, and an int can only hold up to about 2.1 billion. Use long long. samples/big-extra.in is our own test for this (not from Kattis).

Input and output cheat sheet

The basics. Your program reads from standard input (cin) and writes to standard output (cout). Don't open files, and don't print prompts like "Enter a number:". Anything extra you print counts as wrong output. (DOMjudge team manual: "Solutions have to read all input from 'standard in' and write all output to 'standard out'.")

Test locally the way the judge does: g++ -std=c++17 -Wall a.cpp -o a && ./a < a.in

0. Starter template (type this first)

#include <bits/stdc++.h>
using namespace std;
typedef long long ll;

void solve() {
    ll a, b;
    cin >> a >> b;
    cout << a + b << "\n";
}

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);
    int T = 1;
    cin >> T;               // delete this line if there's only one case
    while (T--) solve();
}

In: 2 / 1 2 / 3000000000 1 Out: 3 / 3000000001

  • <bits/stdc++.h> pulls in the whole standard library in one line. It's a GCC file. Kattis compiles C++ with g++, so it works when you submit there. Apple's default compiler on a Mac doesn't have it, so on a Mac list the headers you need instead (<iostream>, <vector>, <string>, <algorithm>).
  • Mistake: forgetting to delete cin >> T; on a problem with one case. Your program reads the first number as T.

1. Count first, then the values

You see: "The first line contains an integer n. The next line contains n integers."

int n;
cin >> n;
vector<int> a(n);
for (int i = 0; i < n; i++) cin >> a[i];

In: 5 / 3 1 4 1 5 Out (sum): 14

  • cin >> skips spaces and newlines, so it doesn't matter if the n values are on one line or many.
  • Mistake: vector<int> a; then a[i] = .... The vector is empty, so that writes past the end. Use vector<int> a(n) or push_back.

2. T test cases, "Case #x:" output

You see: "The first line contains T, the number of test cases." Output: "For each test case, output Case #x: y."

int T;
cin >> T;
for (int t = 1; t <= T; t++) {
    int a, b;
    cin >> a >> b;
    cout << "Case #" << t << ": " << a + b << "\n";
}

In: 3 / 1 2 / 10 20 / -5 5 Out: Case #1: 3 / Case #2: 30 / Case #3: 0

  • Mistake: starting t at 0 (prints Case #0), or missing the space after the colon. Copy the format from the sample output character by character.
  • Mistake: keeping a global counter or array between cases and not resetting it. Declare per-case variables inside the loop.

3. Big numbers: use long long

You see: values up to 10^9 or bigger, or anything that gets added or multiplied together.

int stops at 2,147,483,647 (about 2.1 × 10^9). long long goes up to about 9.2 × 10^18.

long long a, b;
cin >> a >> b;
cout << a + b << "\n" << a * b << "\n";
int x = 100000, y = 100000;
long long good = 1LL * x * y;   // x * y alone overflows as int first
cout << good << "\n";

In: 2000000000 3000000000 Out: 5000000000 / 6000000000000000000 / 10000000000

  • Mistake: long long p = x * y; with int x, y. The multiply happens in int and overflows before it's stored. Write 1LL * x * y.
  • Mistake: reading 3000000000 into an int. cin fails, and every read after that fails too.
  • Put sums of many values and any product in long long.

4. Fast I/O and "\n" vs endl

You see: n up to 10^5 or 10^6, or a time limit you're barely missing.

ios::sync_with_stdio(false);
cin.tie(nullptr);
...
cout << x << "\n";      // not endl
  • endl prints a newline and also flushes the output every time. On a million lines that's slow. "\n" just prints the newline.
  • Mistake: after sync_with_stdio(false), mixing cin/cout with scanf/printf. The output can come out in the wrong order. Pick one.

5. Read until end of file (no count given)

You see: "Input consists of several lines" or "process until end of input," with no n.

long long x, sum = 0;
int count = 0;
while (cin >> x) { sum += x; count++; }
cout << count << " " << sum << "\n";

In: 4 8 / 15 / 16 23 42 Out: 6 108

  • cin >> x returns false when there's nothing left, so the loop stops on its own.
  • Mistake: while (!cin.eof()). When the file ends with a newline (almost always), the loop runs one extra time and the failed read leaves the last value in x, so it gets counted twice (on the sample: 7 150). Put the read inside the while.
  • To type end of file by hand in the terminal: Ctrl+D (Mac/Linux). Easier to use ./a < a.in.

6. Sentinel end ("ends with 0 0")

You see: "The input ends with a line containing 0 0, which should not be processed."

int a, b;
while (cin >> a >> b) {
    if (a == 0 && b == 0) break;
    cout << a * b << "\n";
}

In: 2 3 / 4 5 / 7 0 / 0 0 Out: 6 / 20 / 0

  • Mistake: printing an answer for the 0 0 line. Check for the sentinel right after reading, before doing anything else.
  • Mistake: stopping when only one value is 0 (7 0 above is a real case). Check exactly what the statement says ends the input.

7. Output formatting: decimals and spaces

You see: "Print the answer rounded to 2 decimal places" or "print the values on one line separated by spaces."

cout << fixed << setprecision(2) << (double)sum / n << "\n";   // needs <iomanip>
for (int i = 0; i < n; i++) {
    if (i > 0) cout << " ";
    cout << a[i];
}
cout << "\n";

In: 3 / 1 2 2 Out: 1.67 / 1 2 2

  • fixed << setprecision(2) means exactly 2 digits after the decimal point. Without fixed, setprecision(2) means 2 digits total (1.7).
  • Mistake: sum / n with two ints. That's integer division (5 / 3 is 1). Cast one side to double first.
  • Whitespace: by default the judge's checker treats any run of spaces and newlines as the same, and decimals must match exactly unless the problem gives an allowed error (problem package format spec; the DOMjudge manual says "some extra whitespace may be ignored," depending on the problem). Don't count on it. Match the sample output's format exactly.
  • If the problem says "absolute or relative error of at most 10^-6," print more digits than that (setprecision(9)).

8. Grids: R C, then R lines of characters

You see: "The first line has R and C. The next R lines each have C characters" (. open, # wall, S start).

int R, C;
cin >> R >> C;
vector<string> g(R);
for (int r = 0; r < R; r++) cin >> g[r];
// g[r][c] is row r, column c

In: 3 4 / #..# / .S.. / ##.# Out: 5 walls, start at 1 1

  • cin >> g[r] reads one row because rows have no spaces. If a row can contain spaces, use getline (section 10).
  • Mistake: mixing up g[r][c] and g[c][r]. Row first, then column. Also check bounds (0 <= r < R, 0 <= c < C) before looking at a neighbor.

9. A record per line, then sort

You see: "Each of the next n lines contains a name and a score." Output: "sorted by score, highest first; break ties by name."

struct Player { string name; int score; };
vector<Player> p(n);
for (auto& x : p) cin >> x.name >> x.score;
sort(p.begin(), p.end(), [](const Player& a, const Player& b) {
    if (a.score != b.score) return a.score > b.score;
    return a.name < b.name;
});

In: 4 / bob 70 / amy 90 / cal 70 / dee 85 Out: amy 90 / dee 85 / bob 70 / cal 70

  • Mistake: forgetting the tie-break. Two players with 70 can come out in either order, and the judge expects one.
  • Mistake: using >= or <= in the compare. It has to be strict (> or <) or sort can crash.
  • Quick version: vector<pair<int,string>> sorts by the first field, then the second, with no compare function.

10. Whole lines with spaces: getline

You see: "Each line contains a full name" or a sentence, so the text has spaces in it.

int n;
cin >> n;
cin.ignore();              // throw away the '\n' left after n
for (int i = 0; i < n; i++) {
    string line;
    getline(cin, line);
    cout << "Hello, " << line << "!\n";
}

In: 2 / Ada Lovelace / Grace Brewster Hopper Out: Hello, Ada Lovelace! / Hello, Grace Brewster Hopper!

  • cin >> s stops at the first space. getline(cin, s) reads up to the end of the line.
  • The bug: cin >> n leaves the newline after n sitting in the input. The first getline reads that, so you get an empty first line and lose the last real one. Without cin.ignore() the output above is Hello, ! / Hello, Ada Lovelace!.
  • Fix 1: cin.ignore(); once after the last cin >>. Fix 2: getline(cin >> ws, line); skips all spaces and newlines before the line starts. Fix 2 also skips blank lines, so don't use it when a blank line means something.

11. Unknown count per line: stringstream

You see: "Each line contains some integers" with no count, and you need an answer per line.

string line;
while (getline(cin, line)) {
    stringstream ss(line);          // needs <sstream>
    int x, sum = 0, count = 0;
    while (ss >> x) { sum += x; count++; }
    cout << "count " << count << ", sum " << sum << "\n";
}

In: 1 2 3 / 10 / 5 5 5 5 5 Out: count 3, sum 6 / count 1, sum 10 / count 5, sum 25

  • stringstream ss(line) lets you use >> on one line only, the same way you use it on cin. Works for words too: string w; while (ss >> w).
  • Mistake: reading with cin >> here. cin doesn't stop at the end of a line, so you can't tell where one line ends and the next begins.

Before you submit: run every sample. Check the output format against the sample character by character. Remove debug prints. Check long long anywhere numbers get big.
