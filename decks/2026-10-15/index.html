How does code from your laptop get onto that chip?

How upload works

How code gets onto the board

  1. You write a sketchArduino's word for a program. It's C++
  2. Verify turns the sketch into numbersTypos get caught here
  3. Upload sends them down the cableThe board restarts to take them in
  4. The board saves them and runs themThey stay, even with the power off

Fills in on its own. One press shows the rest. The next press moves on.

This is the whole crash course. The chip can't read C++. So the IDE does two jobs. Verify (the check mark) turns the sketch into the chip's numbers. Upload (the arrow) does that again, then sends the numbers down the cable.

During Upload, the IDE restarts the board. For a moment after every restart, a small program that always lives on the chip waits for new code. It saves the new code and starts it. The TX and RX lights flicker while the code goes by. If someone asks, that small program is called the bootloader.

The board holds one program at a time. New code replaces the old code. The bootloader takes 512 bytes of the 32 KB, so the IDE says 32,256 bytes are free (Arduino AVR core 1.8.8, boards.txt).

So who runs setup() and loop()? Arduino does, from a main() you never see.

What Arduino runs for you

// Arduino's main.cpp, made simpler
int main() {
  init();          // get the board ready
  setup();         // your setup(), once
  while (true) {
    loop();        // your loop(), forever
  }
}

A sketch is C++, and every C++ program starts at main(). Arduino writes main() for you. It runs setup() once, then runs loop() over and over, forever. setup() only runs again after a restart.

This is a simpler copy of Arduino's real main.cpp (checked 2026-10-07). The real one uses for (;;), which does the same thing as while (true).

Now the fan. A pin can't power it, so the fan needs a switch.

Fan

A pin can flip the fan's switch

  1. The fan needs more power than a pin givesA motor on a pin can break the board
  2. A transistor is a switchA little into the middle leg lets a lot through
  3. The power comes from the modulePin 5 only flips the switch
  4. A diode protects the transistorA stopping motor pushes back a jolt

Fills in on its own. One press shows the rest. The next press moves on.

Aim to be here by 2:04. Arduino says a pin is safe up to 20 mA, and 40 mA is the absolute limit. The fan needs far more. Elegoo's tutorial (lesson 29) warns that a motor on a pin can damage the board.

The transistor has three legs. With the flat side facing you: left goes to ground, middle comes from the pin, right goes to the fan (PN2222A datasheet). A little electricity into the middle leg lets a lot flow through the other two. If anyone asks, the legs are called emitter, base, and collector.

The 220 ohm resistor keeps pin 5 to about 17 mA. The diode sits across the fan, stripe toward +. When the fan turns off, the motor pushes back a short jolt. The diode gives that jolt a safe path, so it doesn't hit the transistor.

Aim to be here by 2:13. This is the big idea today. myservo.write(90) takes almost no time. The board sends the angle and goes straight to the next line. If the next line turns on the fan, the fan starts while the arm is still moving.

The servo has no wire that tells the board where the arm is. So the code waits on purpose: one degree, then 15 ms, 91 times (0 to 90 is 91 numbers). When the for loop ends, the arm has had time to get there. Then the next line can start the fan.
