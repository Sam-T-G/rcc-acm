## 1. Every part, named

| Part | What it is, in plain words | Used in |
|---|---|---|
| Breadboard (830 holes) | White board with holes. Each short row of 5 holes is connected inside; the long rails along both edges carry power (+, red line) and ground (-, blue line). | All rounds |
| Power supply module | Small board that clips onto one end of the breadboard. Takes 6.5 to 9 V in through a round barrel jack and puts 5 V (or 3.3 V) on the rails. Has an on/off switch, a power light, and one jumper per side to pick 5 V, 3.3 V, or OFF. | LED, button loop, fan |
| 9V battery with DC plug | A 9 V battery on a cable that ends in a barrel plug. Plugs into the power module. | LED, button loop, fan |
| 9V 1A wall adapter | Does the same job as the battery, from a wall outlet. Backup for a dead battery. | Spare |
| UNO R3 board (Elegoo) | The Arduino: a small computer that runs one program over and over. Copy of the Arduino UNO. | Blink, servo, button |
| USB cable (A to B) | Power and code from the laptop to the board. | Blink, servo, button |
| Jumper wires, male to male | Wires with a metal pin on both ends. | All rounds |
| Red LED (5 mm) | A light that only works one way around. The long leg is +. | LED, button loop |
| 220 Ω resistor | Slows the electricity so the LED doesn't burn out. Use the ones labelled 220; the stripes are hard to read. | LED, button loop |
| Push button (small, 4 legs) | A gap you close by pressing. The legs are connected inside in two pairs; opposite corners always go through the button. | Button loop, button + if |
| Fan blade and 3 to 6 V DC motor | Small motor; the plastic blade pushes onto its shaft. | Fan |
| Servo, SG90 | A motor that turns to an angle from 0 to 180 degrees and holds it. Three wires: brown = ground, red = 5 V power, orange = signal. Comes with plastic arms (horns) that push onto the top. | Servo, button + if |

Kit parts we are **not** using today (so tables don't go looking): the L293D chip, transistors, relay, stepper motor, sensors, and displays.

### Gaps and risks

1. **UNO R4 WiFi cables.** The R4 WiFi has a USB-C port, and the order had no USB-C to USB-C or USB-A to USB-C cables. The 6 cables we bought are USB-B to USB-C, which fit the Elegoo UNO R3 boards for laptops with only USB-C ports. Bring USB-C cables if the R4 boards will be used.
2. **USB-C laptops.** The kit cable is USB-A to USB-B. MacBooks and many newer laptops only have USB-C, so hand out the 6 USB-B to USB-C cables.
3. **9V batteries.** One per kit, of unknown age. Test each one before the meeting (power light on, LED lights). The 9V adapters are the backup, but they need outlets near the tables.
4. **Some boards come with Blink already loaded, some don't.** Elegoo says theirs generally do (tutorial lesson 2), but at least one officer's board didn't. The L light may blink slowly before anyone uploads, or stay off. Either way, the deck has people change the delays to 200 before uploading, so a fast blink is unmistakably their own upload.
5. **Servo power over USB.** Elegoo's own servo lesson powers the SG90 from the UNO's 5V pin, so this normally works. If a board resets or the servo jitters, use the fallback in section 3.
6. **Split rails [CHECK].** On some 830-hole breadboards, the red and blue lines have a gap in the middle, which means the rail is cut in two. Look at one board. If the lines break, keep the LED circuit on the same half as the power module.
7. **Motor wires [CHECK].** Look at one kit's motor. If its two wires are too thin or floppy to push into a rail hole, have tables hold them against two jumper wires that are plugged into the rails.
8. **Servo library.** The Arduino IDE ships with the Servo library. If a laptop has no File → Examples → Servo, open the Library Manager and install "Servo" (version 1.3.0 tested here).

## 3. Where the power comes from

Today there are **two separate power systems**, and they never need to touch.

**A. The breadboard rails: battery → power module → rails.** Used for the LED, the button loop, and the fan.

- The 9V battery's barrel plug goes into the power module's jack. The wall adapter is the alternative.
- The module puts 5 V on the + rails and ground on the - rails. Both sides of the board are powered when both jumpers are on 5V.
- Its limit is 700 mA, plenty for an LED and a small motor.
- The switch turns it on and off. The power light shows it's on.
- If both jumpers are on OFF, nothing turns on (Elegoo).

**B. The Arduino: laptop USB → UNO → its 5V and GND pins.** Used for the board itself, the servo (its red wire goes to 5V), and the button input.

**The only time they connect** is the servo fallback. If USB can't supply enough power:

1. Move the servo's red wire to the breadboard's + rail.
2. Add a jumper from a UNO GND pin to the breadboard's - rail.

That shared ground is required: without it, the servo can't read the signal (slide 24).

**Never do these:**

- Connect the UNO's 5V pin to the module's + rail. Two supplies would be fighting each other.
- Plug the 9V battery straight into the breadboard.
- Put the module on backwards. Its - pin goes on the blue line and its + pin on the red line, or the power is reversed (Elegoo's warning).
- Wire + straight to - with nothing in between. That's a short.

## 5. Step by step, round by round

**Hole names.** a10 means the hole in line a at number 10: the letters a to j are printed down the side, the numbers along the top.

**Breadboard map.** The rows are numbered along the long side (1 to 63 on an 830-hole board). Each row has holes a to e on one side of the middle gap and f to j on the other. The rails run along both long edges. "Row 10" means any hole a to e in row 10 unless a letter is given.

### Round 0: Find your parts (slide 9, 2 min)

Each table lays these out:

- breadboard, power module, 9V battery
- UNO board, USB cable, jumper wires
- red LED, 220 Ω resistor, button
- fan blade, motor, servo with its arm

Everything else stays in the box.

### Round 1: Light an LED, no code (slides 12 to 19, 4 min)

1. **Place the power module.** Press it onto one end of the breadboard so its pins go into the rails. Its - pin goes on the blue line and its + pin on the red line, on both sides.
2. **Set the jumpers.** Find the two small caps (jumpers), one on each side of the module. Pull each one off and push it back on over the pins labelled **5V**.
3. **Connect the battery.** Make sure the module's switch is **off**. Snap the battery cable onto the 9V battery if it isn't already, then push its round plug into the module's jack.
4. **Resistor.** Take one resistor labelled 220 and bend both legs down. Plug one leg into any hole in the top **+ rail** and the other leg into **a10**.
5. **LED.** Take one red LED. Plug its **long leg into c10** and its short leg into **c11**.
6. **Ground jumper.** Take a jumper wire. Plug one end into **a11** and the other end into any hole in the top **- rail**.
7. **Trace the loop with a finger:** + rail → resistor → row 10 → LED long leg → LED → short leg → row 11 → jumper → - rail.
8. **Switch the module on.** The module's light and the LED both turn on.

If it doesn't work:

- **Nothing lights, not even the module.** Check that both jumpers are on 5V and the battery is good.
- **The module lights but the LED doesn't.** The LED is backwards, so flip it. Or a leg is one row off.

**Check in:** pull out the a11 jumper and the LED goes dark. Put it back.

### Round 2: Add a button to the loop (slides 20 to 24, 3 min)

1. Switch the module **off**.
2. **Place the button across the middle gap,** with its legs in **e15, e17, f15, f17**. It only fits one way. If it won't sit flat, turn it 90 degrees.
3. **Rewire the ground.** Remove the jumper from a11 to the - rail. Add a jumper from **a11 to a15**, and one from **j17 to the bottom - rail**. a15 and j17 are opposite corners of the button.
4. Switch on. Press the button and the LED lights. Let go and it goes dark.

If it doesn't work:

- **Always lit:** the two jumpers are on legs that are connected inside. Move one jumper to the opposite corner.
- **Never lit:** the button isn't across the gap.

**After the check-in:**

1. Remove the button and its two jumpers.
2. Put back the jumper from **a11 to the top - rail**.

The LED now stays on whenever the rails have power. Keep the button for later.

### Round 3: Spin the fan, no code (slides 25 to 28, 2 min)

1. Push the fan blade firmly onto the motor's shaft.
2. With the module **on**, hold the motor away from the board, keeping fingers clear of the blade.
3. Touch or push one motor wire into a **+ rail** hole and the other into a **- rail** hole. Use the far end of the board, away from the LED. It spins.
4. Swap the two wires. It spins the other way.
5. Pull the wires out and switch the module **off**. The breadboard part of the lab is done. Leave the LED circuit where it is.

### Round 4: First upload, Blink (slides 29 to 36, 4 min)

1. Plug the UNO into the laptop. Use the kit cable, or a USB-B to USB-C cable for a USB-C laptop.
2. In Arduino IDE 2, pick the board in **Tools → Board → Arduino AVR Boards → Arduino Uno**. For an R4 WiFi, first install "Arduino UNO R4 Boards" in the Boards Manager, then pick UNO R4 WiFi.
3. Pick the port in **Tools → Port**. It's the one that appears when the board is plugged in.
4. Open **File → Examples → 01.Basics → Blink**.
5. Change **both `delay(1000);` lines to `delay(200);`**.
6. Click **Upload**, the round arrow button at the top left. The TX and RX lights flicker, then the L light blinks fast, about 2 to 3 times a second. Whether the board started with a slow Blink or nothing, fast means the upload worked.

If it doesn't work:

- **No port:** try another cable, since some only charge. Still no port on a Windows laptop: it may need the USB driver; Elegoo's tutorial, lesson 0, covers installing it from Device Manager. The kit board's main chip is the ATmega328P; the USB chip isn't named in Elegoo's kit listing (Elegoo sells its standalone UNO R3 as ATmega328P + ATmega16U2).
- **"Upload error":** recheck the board and port.

**Check in:** try `delay(50);`, upload again, and it's even faster.

### Round 5: Make the servo sweep (slides 37 to 45, 5 min)

1. **Unplug USB.**
2. Push three **male-to-male** jumper wires into the servo's plug, one per hole.
3. **Brown wire → GND** on the UNO's power header (the row labelled IOREF, RESET, 3.3V, 5V, GND, GND, Vin).
4. **Red wire → 5V** on the same header.
5. **Orange wire → digital pin 9.**
6. Open **File → Examples → Servo → Sweep**. Its servo is on pin 9 already.
7. Plug USB back in, check the board and port, and **Upload**. The arm sweeps from 0 to 180 and back.

If it doesn't work:

- **Doesn't move:** check the orange wire is on pin 9 and the brown wire is on GND.
- **Board resets or the servo jitters:** use the power fallback in section 3.
- **Buzzes at the ends:** change 0 and 180 to 10 and 170.

**Check in:**

- Change both `180`s to `90` and it only goes halfway.
- Change both `delay(15)` to `delay(5)` and it's faster.

### Round 6: Press to turn (slides 46 to 53, 5 min)

1. **Unplug USB.**
2. **Place the button across the middle gap** at **e21, e23, f21, f23**, away from the LED circuit.
3. **Corner to pin 2.** Take a jumper wire. Plug one end into **a21** and the other end into the pin labelled **2** in the UNO's digital row.
4. **Opposite corner to GND.** Take another jumper wire. Plug one end into **j23** and the other end into the **GND** pin next to pin 13; the servo already uses one on the power header. This button doesn't touch the breadboard rails.
5. In the Sweep sketch, add this line inside `setup()`, under `myservo.attach(9);`:

   ```cpp
   pinMode(2, INPUT_PULLUP);
   ```

6. Replace `loop()` with:

   ```cpp
   void loop() {
     if (digitalRead(2) == LOW) {
       myservo.write(90);   // pressed
     } else {
       myservo.write(0);    // let go
     }
   }
   ```

7. Plug in and upload. Hold the button and the arm turns to 90. Let go and it goes back to 0.

If it doesn't work:

- **Never goes back:** move a wire to the opposite corner.
- **Twitches randomly:** the `INPUT_PULLUP` line is missing.

### Round 7: Change the rules (slides 54 to 55, 5 min)

Pick one, then another. Each answer below was tested on the UNO and the UNO R4 WiFi; the full sketches are in `scratch/2026-10-08-deck/sketches/ex_*` (gitignored, local).

**Flip it.** Swap the `90` and the `0`, so pressing sends it back.

**Hold to turn slowly** (a `while` loop). `pos` already exists from Sweep. Let go and it stops where it is. The board's reset button starts it over, because reset runs `setup()` again.

```cpp
void loop() {
  while (digitalRead(2) == LOW && pos < 180) {
    pos++;
    myservo.write(pos);
    delay(15);
  }
}
```

**Second button on pin 3** (`else if`).

1. Place a second button at **e26, e28, f26, f28**.
2. Jumper from **a26 to pin 3**, and from **j28 to the third GND pin**. That's the other GND on the power header if the servo's brown wire took one.
3. Add `pinMode(3, INPUT_PULLUP);` to `setup()`.
4. Replace `loop()` with:

```cpp
void loop() {
  if (digitalRead(2) == LOW) {
    myservo.write(180);
  } else if (digitalRead(3) == LOW) {
    myservo.write(0);
  } else {
    myservo.write(90);
  }
}
```

**Harder: tap on, tap off.** Add these two lines above `setup()`, then replace `loop()`:

```cpp
bool turned = false;
int last = HIGH;

void loop() {
  int now = digitalRead(2);
  if (last == HIGH && now == LOW) {   // the moment it goes down
    turned = !turned;
    myservo.write(turned ? 90 : 0);
    delay(50);                        // let the button settle
  }
  last = now;
}
```
