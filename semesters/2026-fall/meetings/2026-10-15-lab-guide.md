# Lab guide: first upload, then a fan that waits for the arm (Thursday 2026-10-15)

The officer's companion to `2026-10-15-deck.html`. Last week's lab never reached the Arduino, because the breadboard rounds took the whole time. So this lab starts with the board. First a short talk on how code gets onto it. Then one build that grows each round. By the end, every table has a button that turns the servo to 90 degrees, and the fan starts only after the arm gets there.

Anything not confirmed is marked **[CHECK]**. On 2026-10-14 seven reviewers walked every step against the kit's manual, Elegoo's photos, the installed Arduino IDE 2, and the library code; their fixes are in the deck and below.

## 1. Every part, named

| Part | What it is, in plain words | Used in |
|---|---|---|
| UNO R3 board (Elegoo) | The Arduino, a blue board. A small computer that runs one program over and over. Main chip: ATmega328P, with 32 KB for code. | Every round |
| USB cable (A to B) | Brings power and code from the laptop to the board. The square end goes in the UNO. | Every round |
| jumper wire, male to male | A loose wire with a metal pin on both ends. The kit's female-to-male wires on a ribbon don't fit the UNO. | Every round |
| servo, SG90 | A blue motor that turns to an angle from 0 to 180 and holds it. Brown = ground, red = 5V, orange = the angle. | Servo onward |
| servo arm | The plastic piece pushed onto the servo's shaft. The arms come loose in a small bag with screws. | Servo onward |
| button | A small black square with four legs. Pressing it joins the two sides. Opposite corners always go through the button. | Button onward |
| breadboard (830 holes) | Where circuits get built. Each 5-hole strip is joined inside. The rails run along the long edges, marked red (+) and blue (-). | Button, fan |
| power module | A black board on the row-1 end of the breadboard. Turns the battery's 9V into 5V on the rails, up to 700 mA. It has a round jack for the battery, a square push switch next to it, a light, a flat USB socket, and two 5V / OFF / 3.3 caps. | Fan |
| 9V battery | A clip on the battery ends in a round plug for the module's jack. The 9V adapter does the same from an outlet. | Fan |
| **transistor, PN2222 (new)** | Small black part with one flat side and three legs. A switch with no moving parts: a little electricity into the middle leg lets a lot through the other two. With the flat side facing you, the legs are emitter, base, collector (E, B, C). | Fan |
| **diode, 1N4007 (new)** | Small black tube with a gray stripe at one end. Lets electricity through one way only. Across the fan, stripe toward +, it gives the motor's jolt a safe path when the fan stops. | Fan |
| 220 Ω resistor | Small and blue with five stripes: red, red, black, black, brown. Keeps pin 5's current small. | Fan |
| fan blade + motor | A small silver motor with a red and a black wire that end in pins. The white blade with a yellow center pushes onto its shaft. | Fan |

Kit parts we are **not** using today: the LED, the L293D chip, the S8050 transistors, the relay, the stepper, sensors, and displays. An S8050 has the same leg order as the PN2222, so a table that grabs one by mistake still gets a working fan.

**So:** 6 full stations, two or three people each, covers 12 to 18 people.

**Overflow:** the 3 UNO R4 WiFi boards make code-only stations. They do Blink, the servo, and the button (slides 7 to 37), then join a full table for the fan. Each needs:

- a spare breadboard, a spare SG90 with its arm already on, jumpers, and a button borrowed from a kit;
- **a USB-C data cable** that fits the R4 and the laptop (the club owns none);
- a laptop that already has **Arduino UNO R4 Boards** installed in the Boards Manager. Installing it mid-round eats the round.

Don't build the fan switch on an R4 with a 220 Ω resistor. Its pins are rated for 8 mA (UNO R4 WiFi datasheet), and 220 Ω draws about 17 mA. If someone tries it, use a 1 kΩ resistor.

### Gaps and risks

1. **PN2222 print [CHECK].** Open one kit. Check that the transistors say PN2222 or PN2222A on the flat side. The PN2222A order (Fairchild datasheet) is E, B, C with the flat side facing you, and so is the S8050's. Parts printed 2N2222A or P2N2222A can have their legs in a different order (C, B, E on some). If the print says anything else, look up that part's leg order before the lab.
2. **Backwards diode.** With the stripe away from +, nothing happens at first. When the transistor turns on, + connects to - through the diode and the transistor, and the transistor can get hot enough to burn a finger. **Officers check every stripe before slide 47. Nobody touches a transistor to test it.** Bring spare PN2222s (each kit has 5).
3. **The fan blade.** The blade is wider than the motor, so a motor lying on the table hits the table, stalls, and heats the transistor. The slides have one person hold the motor up by its silver body, blade in the air, whenever the module is on (slides 47 and 56).
4. **A board wire in the wrong hole.** A wire from a + rail straight to pin 5 would damage the pin on upload. Slide 48 has tables pull the test jumper out and use a fresh jumper from j11 to ~5, so nobody moves the wrong end. A ground jumper in a + rail spins the fan. Slide 50 catches both: module on, USB still out, and nothing should happen (no fan, no UNO lights).
5. **Batteries [CHECK].** The kit battery is an "Extra Heavy Duty" carbon-zinc 9V, and it ran last week. Its light comes on long after it's too weak for a motor. Test each one by running a fan for 10 seconds (section 4). Slow fan: use that kit's 9V adapter, which needs an outlet near the table.
6. **USB-C laptops.** Hand out the 6 USB-B to USB-C cables, and collect them at pack-up.
7. **The servo starts at 90.** `attach()` starts the servo at 90 (Servo 1.3.0, DEFAULT_PULSE_WIDTH 1500). The button round adds `myservo.write(0);` to setup() so it starts at 0.
8. **Servo on USB power.** Elegoo's lesson powers the SG90 from the 5V pin, and Arduino's Servo docs say one or two servos are fine there. If a board still restarts when the arm moves:
   1. Unplug USB.
   2. Check that the module's switch is off. Push the battery's plug into the module's round jack.
   3. Take a jumper wire. Plug one end into any hole in the bottom - rail (blue line) and the other into the second GND in the UNO's short row of power pins.
   4. Move the free end of the jumper on the servo's red wire from 5V to any hole in the top + rail (red line).
   5. Switch the module on. Plug USB back in.

   That table now has the slide 49 jumper and the battery already in. At the fan round it skips slide 40 and checks its existing jumper at slide 49 instead of adding a second one. If it can, it uses the 9V adapter, since the servo and the fan now share the module.
9. **The board's orientation.** The club's Elegoo boards (product photo; manual p.193) print the rows counting up from 1 at one end, and the module only fits, + on red, at the row-1 end. Slide 29 turns every board so the module is on the right and the letters read upright, which puts line a at the far edge. That is the view every board picture shows. **[CHECK]** one real board: module on the right, row 1 next to it, line a at the far edge, red line above blue on both edges. Also check that the rails run unbroken end to end (Elegoo's photos show unbroken lines). The build sits in rows 1 to 23 next to the module, so a split wouldn't matter today, but write it down. See [breadboard-drawing.md](../../../docs/03-playbooks/arduino-lab/breadboard-drawing.md).
10. **ICPC form [CHECK].** The wrap slide's QR is the same form as 09-24 and 10-08 (`forms.gle/YvL7dB2QUyU4aH5D8`). Confirm it's still open.

## 3. Where the power comes from

**A. The Arduino: laptop USB → UNO → its 5V and GND pins.** Powers the board, the servo (red to 5V, brown to the first GND), and the button (pin 2 and the GND next to pin 13).

**B. The breadboard rails: 9V battery → power module → rails.** Powers only the fan, through the transistor.

**The one place they touch:** the jumper from the bottom - rail to the UNO's second GND in the power row (slide 49). Pin 5's small current goes into the transistor's middle leg, out its left leg into the - rail, and has to get back to the board. That jumper finishes the path. Without it, the fan never turns on. Both - rails are joined through the module, so either one works.

**Never do these:**

- Connect the UNO's 5V pin to the module's + rail.
- Run the motor straight from a pin. A pin is safe at 20 mA, 40 mA absolute (Arduino docs), and Elegoo lesson 29 warns it can damage the board.
- Put the diode in with the stripe away from +.
- Change wires with the power on. Unplug USB and switch the module off first.
- Put the module on backwards. It goes on the row-1 end, - pins on the blue lines, + pins on the red lines.

## 5. Step by step, round by round

**Hole names.** Turn the board as slide 29 says: module on the right, letters upright. Then e21 is the hole in line e (the letters a to j at the left end) and row 21 (rows count up from 1 next to the module, toward the left). The board prints some row numbers; the pictures mark 1, 10, and 20.

**Code to type.** New lines are orange in the picture, and the slide says to type them. A `}` the IDE adds by itself is gray. Arduino IDE 2 adds a `}` whenever you type `{` at the end of a line, so typing the gray ones again leaves extra `}` at the bottom.

### Round 0: Find your parts (slide 6, 2 min)

Every part on the slide's picture. The power module is already on the breadboard. Take 8 jumper wires with a pin on both ends. Leave everything else in the box.

### Talk: how code gets onto the board (slides 3 to 5)

1. **You write a sketch.** That's Arduino's word for a program. It's C++.
2. **Verify (the check mark) turns it into numbers,** the only thing the chip can read. This is called compiling. Typos get caught here, and nothing goes to the board.
3. **Upload (the arrow next to it) sends the numbers down the USB cable.** The IDE restarts the board. For a moment after every restart, a small program that always lives on the chip (the bootloader) waits for new code. It saves the code into memory that keeps it with the power off, then starts it. TX and RX flicker while the code goes by.
4. **The board runs it** (setup() once, then loop() forever) **and keeps it** with the power off. It holds one program at a time. A new upload replaces the old one.

The bootloader takes 512 bytes, which is why the IDE says 32,256 bytes are free (Arduino AVR core boards.txt: `upload.maximum_size=32256`, `bootloader.file=optiboot/optiboot_atmega328.hex`).

### Round 1: First upload, Blink (slides 7 to 16)

1. One laptop per table. Open Arduino IDE 2. Only USB-C ports? Hand them a club cable.
2. Plug the UNO into the laptop.
3. **Tools → Board → Arduino AVR Boards → Arduino UNO** (not UNO Mini or UNO WiFi). R4 WiFi: pick UNO R4 WiFi from Arduino UNO R4 Boards.
4. **Tools → Port**, the one that says Arduino UNO. On a Mac it reads /dev/cu.usbmodem then a number; on Windows, COM then a number. Skip the Mac's Bluetooth port.
5. **File → Examples → 01.Basics → Blink.**
6. Near the bottom (lines 34 and 36), change both `delay(1000);` to `delay(200);`. Leave the notes after `//` alone.
7. Click **Verify** (check mark). The bottom shows the size. Blink is 922 bytes on core 1.8.8; other core versions can be a few bytes off. R4 tables see about 51,800 bytes of 262,144.
8. Click **Upload** (the arrow next to the check mark). TX and RX flicker, then L blinks fast. "Done uploading." shows as a pop-up.

If it doesn't work:

- **No port:** try another cable (some only charge) or another USB port. On Windows, look in Device Manager under Ports (COM and LPT); if nothing appears, reinstall Arduino AVR Boards in the Boards Manager. Macs need no driver. Elegoo's lesson 0 driver steps are for the old IDE 1.8.
- **Upload error:** check the board and the port again.

**Check in (slide 15):** unplug USB and plug it back in; it's still fast. Delete the `;` after the first `delay(200)` and Verify: `expected ';' before 'digitalWrite'`, pointing at the line *after* the missing semicolon (checked 2026-10-12). Other semicolons give other wording. Put it back.

### Round 2: Make the servo move (slides 17 to 26)

1. **Unplug USB.**
2. Push three jumpers into the servo's plug.
3. **Brown → the GND right next to 5V** in the short row of power pins. (The row reads blank, IOREF, RESET, 3.3V, 5V, GND, GND, Vin.)
4. **Red → 5V.**
5. **Orange → ~9** in the long row of digital pins.
6. **File → Examples → Servo → Sweep.** Servo sits under the heading Examples for Arduino UNO. Sweep opens in a new window; use that window from here on. Not Arduino UNO at the top? Pick the board and port again.
7. In loop(), find the two lines that start with `for`. Change the 180 in each to 90. Skip the two 180s after `//`, which are notes. If only the first for line changes, the arm climbs to 90, jumps to 180, and sweeps down. If only the second changes, it climbs to 180, jumps to 90, and sweeps down.
8. Plug in and upload. The arm sweeps 0 to 90 and back. It may sweep to the other side of the picture, depending on how the arm went on. That's fine.

If it doesn't work:

- **No Servo in Examples:** install "Servo by Michael Margolis, Arduino" in the Library Manager (1.3.0 tested).
- **Buzzing at 0:** in the first for line change `pos = 0` to `pos = 10`, and in the second change `pos >= 0` to `pos >= 10`. That table uses 10 for both 0s in Round 3 too.
- **Arm doesn't move:** check that orange is in ~9, not 8 or ~10, and that each jumper is pushed all the way into the plug.
- **Board restarts when the arm moves:** gap 8.

**Check in (slide 26):** change both `delay(15)` to `delay(5)` and upload: faster. Then 40: slower. Put 15 back.

### Round 3: Press to climb (slides 27 to 37)

1. **Unplug USB.**
2. **Set up the breadboard:** turn it so the module is on your right and the letters read upright, line a at the far edge. Put the UNO in front of it.
3. Button over the middle gap: legs in **e21, e23, f21, f23**. It only reaches across the gap one way round; turn it a quarter turn if the legs don't line up.
4. Jumper **a21 → pin 2** in the long row of digital pins.
5. Jumper **j23 → the GND next to pin 13**, in the same long row. Not AREF, which sits right beside it.
6. In setup(), click at the very end of the `myservo.attach(9);` line, after its note. Press Enter and type `myservo.write(0);` and `pinMode(2, INPUT_PULLUP);` (the two orange lines).
7. **Delete the old loop():** select from `void loop()` down to the last `}` at the very bottom, and press Delete. The include line, `Servo myservo;`, `int pos = 0;`, and setup() stay.
8. **Type the new loop():** type the dark lines. The IDE adds the three `}` itself. Then Verify. `pos++` is a short way to write `pos += 1`; it's there so the line fits on the slide.

   ```cpp
   void loop() {
     if (digitalRead(2) == LOW) {
       for (pos = 0; pos <= 90; pos++) {
         myservo.write(pos);
         delay(15);
       }
     }
   }
   ```

9. Plug in, upload, press once. The arm climbs to 90 and stops. When the cable goes in, last round's Sweep runs for a moment until the upload finishes.

If it doesn't work:

- **Verify fails at the bottom:** an extra `}`. Delete it.
- **Nothing on a press:** a jumper is one hole off, the GND jumper is in AREF, or the button isn't pushed all the way in.
- **Climbs again and again with no press:** the INPUT_PULLUP line is missing, or the GND jumper is in j21 instead of j23.

**Check in (slide 37):** press again and the arm jumps back to 0, then climbs, because the for loop always starts at `pos = 0`. Let the room work that out. Challenge 4 fixes it.

### Round 4: Wire the fan switch, no code (slides 38 to 51)

Rows 10 to 12, near the module. With the board turned as in Round 3, rows count up to the left, so row 12 is left of row 10.

1. **Unplug USB.** The servo and button stay wired.
2. Check that the module's switch (the square button next to the round jack) is off. **Push the battery's plug into the round jack.** Light on? Press the switch once.
3. **Transistor:** PN2222 print on the flat side, flat side toward you. Left leg (emitter) **c12**, middle (base) **c11**, right (collector) **c10**.
4. Jumper **a12 → top - rail** (blue line). The left leg goes to ground.
5. **220 Ω resistor e11 → f11**, across the middle gap.
6. **Diode:** stripe-end leg into the **top + rail** (red line), the other leg into **b10**.
7. **Motor:** one wire into **a10**, the other into the **top + rail**.
8. **Test jumper j11 → bottom + rail** (red line). For now it does pin 5's job.
9. **One person holds the motor up by its silver body, blade in the air.** Check the diode's stripe end is in the + rail. Trace the path with a finger (+ rail, motor, row 10, transistor, row 12, - rail). **Switch on.** The fan spins.
10. **Switch off. Pull the test jumper all the way out.** Take a new jumper: **j11 → ~5** in the UNO's long row.
11. Jumper **bottom - rail (blue line) → the second GND** in the UNO's short row of power pins.
12. **Check, then switch on.** Trace both wires to the UNO. Keep USB out. Switch the module on. **Nothing should happen.** If the fan spins or the UNO's ON light glows, switch off and fix it before plugging in USB.

If the fan doesn't spin at step 9, switch off right away and look:

- the diode's stripe;
- the transistor's flat side and print;
- the test jumper is in a + rail;
- the module's light came on.

Spins slowly with everything right: the battery is weak, so use the 9V adapter. Don't touch the transistor to check it.

If the fan spins at step 12, look for one of these:

- the ground jumper is in a + rail;
- the old test jumper is still in a + rail;
- the diode's stripe end went into a - rail.

The UNO's ON light glowing means a wire runs from a + rail to pin 5.

### Round 5: Fan after the arm (slides 52 to 57)

1. In setup(), at the very end of `pinMode(2, INPUT_PULLUP);`, press Enter and add `pinMode(5, OUTPUT);`.
2. In loop(), find the first `}` after `delay(15);` (it lines up with the word `for`). Click just after it, press Enter, and add `digitalWrite(5, HIGH);`.
3. Module still on. Plug in USB. The arm swings to 0 as soon as USB goes in, because last round's sketch already has `write(0)`. Upload. It stays at 0 and the fan stays off.
4. One person holds the motor up. Press once. **The arm climbs to 90, then the fan starts.** The RESET button (the small button next to the USB port) starts it over.

If it doesn't work, the code mistakes all compile, so Verify won't catch them:

- **Fan spins at upload with no press:** the fan line sits after the if's `}`. It belongs between the two `}` after `delay(15);`.
- **Fan starts with the arm:** the fan line went inside the for loop.
- **Arm moves but no fan, wiring right:** setup() is missing `pinMode(5, OUTPUT);`. Without it, HIGH only turns on the pin's weak pull-up.
- **Otherwise:** check the jumper on ~5, the GND jumper, and that the module is on.

The finished sketch, compiled for both boards (not yet run on one):

```cpp
#include <Servo.h>

Servo myservo;
int pos = 0;

void setup() {
  myservo.attach(9);
  myservo.write(0);
  pinMode(2, INPUT_PULLUP);
  pinMode(5, OUTPUT);
}

void loop() {
  if (digitalRead(2) == LOW) {
    for (pos = 0; pos <= 90; pos++) {
      myservo.write(pos);
      delay(15);
    }
    digitalWrite(5, HIGH);
  }
}
```

**Why it waits (slide 52):** `myservo.write()` sends the angle and moves on right away. The servo has no wire that tells the board where the arm is. So the code waits on purpose: one degree, then 15 ms, 91 times (about 1.4 seconds). Sweep's own note says the 15 ms is for "the servo to reach the position". When the for loop ends, the arm is there, and the next line starts the fan.

**Check in (slide 57):** move the fan line right under the if line, upload, press: the fan starts first. Move it back. Then `delay(40)`: a slower climb, and the fan still waits. Short on time, do these once on the projector laptop.

### Round 6: Change the rules (slide 58, 2 min)

**Fan for 3 seconds, then the arm goes back to 0.** Under the fan line, still inside the if, add the lines below. The IDE adds the last `}`.

```cpp
    delay(3000);   // wait 3 seconds
    digitalWrite(5, LOW);
    for (pos = 90; pos >= 0; pos -= 1) {
      myservo.write(pos);
      delay(15);
    }
```

**Slower fan.** Change `digitalWrite(5, HIGH);` to `analogWrite(5, 120);`. 0 is off, 255 is full speed. If the fan won't start, use a bigger number.

**Serial Monitor.** In setup(), add `Serial.begin(9600);`. Under the fan line, add `Serial.println("fan on");`. Open Tools → Serial Monitor and set it to 9600 baud. The same USB cable carries the message back. Opening the Serial Monitor restarts the UNO R3, so the arm goes back to 0 and the fan stops; press again. An R4 WiFi may not restart; press its RESET button.

**Harder: a second press stops the fan and brings the arm back.** Above setup(), add `bool up = false;`. Then:

```cpp
void loop() {
  if (digitalRead(2) == LOW) {
    if (up == false) {
      for (pos = 0; pos <= 90; pos++) {
        myservo.write(pos);
        delay(15);
      }
      digitalWrite(5, HIGH);
      up = true;
    } else {
      digitalWrite(5, LOW);
      for (pos = 90; pos >= 0; pos -= 1) {
        myservo.write(pos);
        delay(15);
      }
      up = false;
    }
    while (digitalRead(2) == LOW) { }   // wait until you let go
    delay(50);                           // let the button settle
  }
}
```
